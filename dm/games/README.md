# Game profiles

The game's constants and shader tables form its profile, a folder `dm/games/<id>/` named after the base game's title ID. This repository has one, Ocarina of Time's `0400486024DEC000`. The folder holds:

- **`game.tsv`**: the game's constants, one `key<TAB>value` row each, with comments on their own lines ([Keys](#keys)).
- **The shader tables** that `shader_split.py` writes: `shader_map.tsv` (+ `.conflicts.tsv`), `shader_facts.tsv`, `shader_pairs.tsv`, and `pso_pairs.tsv` (supplemental agl BAHS program variations). Both pair tables feed vertex output padding and the pipeline prebuild; for a profile without `pso_pairs.tsv`, the packing script keeps the generated table beside the shader package.
- **`shader_facts_manual.tsv`** (optional; Ocarina of Time has none): hand-written translation facts in `shader_facts.tsv`'s row format, for what the machine code cannot tell. `shader_split.py` merges it over the generated rows.
- **`pso_manifest.tsv`**: the prewarm seed list.
- **`shader_seen.tsv`** (optional): shader keys the game's Mac runs asked for. The packing script's `--seen-shaders` builds a partial library of only those, and it stops for a profile without this table ([Building selected Mac shaders](../../docs/development.md#building-selected-mac-shaders)). No other tool reads it, and it is not a shader input.
- **`bench.tsv`** (optional): benchmark routes for `scripts/bench.py` ([A benchmark on the Mac](../../docs/development.md#a-benchmark-on-the-mac)): a name, the scripted input (`DM_KEYS`), the measured window and a description, one route per line.
- **`smoke.tsv`** (optional; Ocarina of Time has none): the route `scripts/regress.py` runs the game on (the script's header describes its keys).
- **`bf_want.tsv`** (optional; Ocarina of Time has none): pixel shaders that get a readable-tile version although they have no rewritable sample (`dmsh_build.py`, `dmsh_fetch.py`).
- **`dual_want.tsv`** (optional; Ocarina of Time has none): pixel shaders a pipeline blends with their output 1 as the second source (dual-source blending); `dmsh_build.py` gives each a dual-source entry point (`fs_dual`). The host lists them with `DM_NVN_DUAL_WANT=<file>`.
- **`validated.tsv`** (optional): the chain the game was last green on, written by `scripts/regress.py check --record` (or `baseline --record`) when its comparison status is `PASS` or `CHANGED` and every tested boot run succeeds. `quick` / `full` rows (the latest of each), `mode<TAB>chain=<DMSH_CHAIN> commit=<short SHA>[+dirty] date=<UTC day> machine=<model> macos=<version>`; a red result leaves the rows as they were. A build using a derived profile does not validate the repository profile. `regress.py list` shows it and whether that chain is the current one. It holds no game data.
- **`geo_mesh.tsv`** (optional; Ocarina of Time has none): vertex / geometry shader pairs drawn with a passthrough geometry shader, by hand, for pairs the prewarm list's `G` rows do not name yet; `dmsh_build.py` builds a mesh library for each pair of both (`dmsh_mesh.py`), and the host draws such a pair's triangle lists as mesh draws ([Passthrough geometry shaders drawn by the vertex shader](../../docs/reference/shaders.md#passthrough-geometry-shaders-drawn-by-the-vertex-shader)). A pair in neither takes the compute path, and the pipeline record names it as a `G` row.
- **`README.md`**: the game's note: what its profile needs and why, what was found on it, how to reach a scene on the Mac, what is still open. Listed in [Games](#games).
- **`patches.py`** (optional): the rewriter's patches of the game's own modules. Keyed by NSO build ID: `CUTS` (byte cuts, each original asserted), `OBS` (observation gates), `FRAME_STEP` (frame-step stubs) and `STUBS` (code a fix needs in the patch area). Placed by a function's fingerprint on any build that keeps the function: `MATCH_CUTS`, `MATCH_FRAME_STEP` and `MATCH_STUBS` ([Function-matched cuts](../../docs/reference/rewriter.md#function-matched-cuts-for-unregistered-builds), [Frame-step stubs placed by their function](../../docs/reference/rewriter.md#frame-step-stubs-placed-by-their-function)). Ocarina of Time's file has only function-matched patches: its frame step with the dynamic resolution stub (`MATCH_FRAME_STEP`) and three movie cuts (`MATCH_CUTS`). `dm/tools/patch_nso.py` loads every profile's file and applies the build-keyed patches of a module's build; a build claimed twice stops the rewrite. A profile in `DM_GAMES_DIR` may have a file too. The patch of Nintendo's `sdk` module, one function-matched rule (the address region manager's node area), is in `dm/tools/sdk_patches.py`. A derived profile uses its repository profile's rules. `dm/tools/tests/test_patches.py` checks that a file names only its own profile's builds. `BINDING` (not read by the rewriter, required by `test_patches.py`) states each patch's binding now, the loosest it could have, its purpose and why ([Binding](../../docs/agents/game-patches.md#binding)); after changing a patch file, a build-keyed host table or a profile key, run `dm/tools/docs_patches.py` to update the [patch index](../../docs/agents/game-patches.md).

The chain version is not in the profile (`dm/gfx/nvn/dmsh_chain.h`, written by `dmsh_chain.py --header`). Two more tables live in the profile folder but are not committed (git ignores them). A full `dmsh_build.py` run makes both from its Mac outputs, so each checkout makes its own, and stamps its libraries with the digest of the profile's inputs (`b-<V>/inputs.tsv`, `dmsh_chain.py --inputs`). The host takes a table only when its header names its library's chain version and that digest.
- **`c1_full.tsv`**: written by `c1_guard.py`. Without it every shader's c1 gets its own 64 KiB.
- **`cb_extent.tsv`**: how far into each uniform slot every shader can read, written by `cb_extent.py`. Without it a uniform block the game updates in part inside a render pass is copied whole.

Everything game-specific belongs here. Code reads the profile; it does not hard-code a game.

| Who | Picks the profile with | Reads |
|---|---|---|
| Shader tools (`shader_split.py`, `dmsh_chain.py`, `dmsh_build.py`, `dmsh_facts.py`) | `DM_GAME=<id>` | tables, `shader_*` keys |
| Host (`make -C dm/host`, `dm/gfx/tests`) | `GAME=<id>` | `gen/<id>/game_profile.h`, generated from `game.tsv` by `game.py header` |
| `scripts/build_app.py` | the NUP's title ID | everything above. A version the profile does not register is built from a [derived profile](#a-new-version-of-the-game) outside the repository |

Without `DM_GAME` or `GAME` they take Ocarina of Time's profile (`game.DEFAULT`; `GAME ?=` in the Makefiles); the two name another only for a derived profile, which the tools find through `DM_GAMES_DIR` (folders separated by `:`, searched after `dm/games`; `DM_GAMES_FIRST=1` searches them first). To query a profile:
- `python3 dm/games/game.py list` lists the profiles.
- `python3 dm/games/game.py <id> <key>` prints one key.

**Launcher settings.** `settings.tsv` lists the player-facing settings once (the environment variable each sets, its kind, default, the condition under which a game offers it and its section in the settings window, **Game**, **Controls** or **Performance**; its header describes the columns). A profile key a setting defaults to (`DM_GAME_<NAME>`) is the value the game was tested with, which the player page [docs/settings.md](../../docs/settings.md#tested-defaults) explains. The packing script runs `settings.py <id> <rewritten modules> <control.nacp> <out.json>`, which keeps the rows that hold for the game: a profile macro (`DM_GAME_FPS_TARGET!=0`), a key in `main`'s rewriter table (`DYNAMIC_RESOLUTION`, written by `patch_nso.py` for a build with that stub), the game's languages, a module that imports the SDK's microphone input. `dm/mac/pack_app.py` puts the result into the app as `Contents/Resources/dm/launcher.json`, for the app's settings window (`dm/mac/Launcher.swift`) and front ends. A row's optional last column, `meta`, carries `key=value` fields front ends read (`level=basic`, `needs=<VAR>=<value>`; [Front ends](../../docs/frontends.md#the-settings-list), with the JSON Schema in `docs/launcher.schema.json`). A new player setting is one row; diagnostic switches stay environment-only.

## Keys

`dm/games/game.py` reads a profile; `game.py header` checks the values below and writes the host's `game_profile.h`. A key Ocarina of Time's `game.tsv` does not set has the default given.

| Key | Meaning |
|---|---|
| `title_id`, `program_id` | Identity. `program_id` is what `svcGetInfo(ProgramId)` reports |
| `name` | The game's name: a label for `game.py list`, error messages, the Mac window's title and its quit prompt. The Mac app's name is the game name in the NUP's control data, else this one, and its bundle ID is `org.nxnative.<title ID in lowercase>`; the packing script's `--app-name` / `APP_NAME` and `--bundle-id` / `BUNDLE_ID` override them |
| `app_category` | The Mac app's App Store category (`LSApplicationCategoryType`) |
| `build <ver> <display version> <module>=<build ID>…` | One row per version the game was brought up on. The packing script builds any version (the base game alone, any update): a registered one from the profile as it is, any other from a profile derived from it ([A new version of the game](#a-new-version-of-the-game)). The host reports the display version by `main`'s build ID |
| `package` | The version the profile's tables, prewarm list and notes were made on. No tool reads it from the repository profile; a derived profile carries the version it was made for. The packing script packs the newest version in the NUP (`-p` / `PACKAGE` picks another) |
| `shader_versions` | Versions whose union the shader tables are (base game first). A registered version is built from the profile as it is only when all of them are in the NUP; otherwise from a derived profile, with tables from the packed version alone |
| `modules` | Code modules rewritten and loaded, in load order. `rtld` is replaced by the host. Each `build` row names its own modules, and the host loads the modules of the row of `main`'s build (`main.c` `profile_modules`, `game.py modules`; all of `modules` for a build with no row). A module a row names that `modules` does not list stays unloaded |
| `romfs_marker` | A path that must exist in the RomFS (the Mac app's `DMRomfsMarker`, which its launcher checks when the RomFS is a folder) |
| `mem_reserve`, `mem_alias`, `mem_stack`, `app_pool` | Guest address-space partition and application pool (`hle_svc.c`). The heap region is the reserve less `mem_alias`, `mem_stack` and 256 MB; the alias region itself is [at least the Switch's 64 GB](../../docs/reference/memory.md#the-macs-alias-region-is-the-switchs-64-gb) |
| `mem_used` | Memory `GetInfo(UsedMemorySize)` reports beside the heap (default `0x4000000`, 64 MB), which `SetHeapSize` and `MapPhysicalMemory` charge too: a game that sizes its heap as total − used gets the pool less this ([Heap sized from the application pool less used memory](../../docs/reference/memory.md#heap-sized-from-the-application-pool-less-used-memory)) |
| `sys_resource` | The system resource size the NPDM declares (main.npdm META +0x14), which `GetInfo(TotalSystemResourceSize)` reports (`hle_svc.c`). The SDK's `IsVirtualAddressMemoryEnabled` is "that size is not 0". Default 32 MB; Ocarina of Time's NPDM declares 48 MB |
| `game_args` | Arguments the game gets when the command line gives none, split at spaces; `dmhost <dir> -- …` overrides them (`main.c`). Empty by default |
| `game_env` | `KEY=VALUE` pairs, separated by spaces, that the game's `getenv` returns (`hle_os.c`). Empty by default. `DM_GAME_ENV` overrides it |
| `mem_map_limit` | `on` / `off` (the default): `MapPhysicalMemory` fails with ResultLimitReached when it would take the process past the application pool (the pool less the used memory `GetInfo` reports), as on Horizon (`hle_svc.c`). Ocarina of Time sets it on |
| `present_interval` | `game` (the default): frames are paced by the present interval the game sets, as on the console (a frame presented with interval 2 stays on screen for two display ticks). `display`: one frame per display tick whatever the game asks, which is only right for a game whose logic does not count frames. `DM_PRESENT_INTERVAL=game` / `display` overrides it |
| `present_snap` | `on` / `off` (the default): present snapshots by default (`nvn_mtl.m` `mtl_snap_on`, a ring of 2 host textures): each present is copied and the game's swapchain texture is free at once ([Present snapshots](../../docs/reference/frame-rate.md#present-snapshots-the-games-swapchain-texture-free-at-once)). The launcher's **Frame buffering** defaults to it, and `DM_PRESENT_SNAP` overrides it |
| `enc_thread` | `on` / `off` (the default): Metal encoding on its own thread by default (`nvn_rec.h` `rec_on`; `DM_NVN_ENC_THREAD=1` / `0` and the launcher's Encode thread override it). For a game that waits on its fence every frame, whose submit thread would otherwise also encode before the wait. Ocarina of Time sets it on (its `game.tsv` has the measurement) |
| `fps_target` | Frame rate cap of the rewriter's frame step, for a `main` that has one (`FRAME_STEP` or `MATCH_FRAME_STEP` in the profile's `patches.py`). `0` (the default): the game's own step. `30` / `60`: the host decides each frame's step in whole vsyncs and keeps the frame on screen that long (`hle_nvn.c` `fstep_tick`, `nvn_fstep.h`): 1 at a 60 cap, 2 when 60 does not hold or at a 30 cap; while a movie plays the step follows the movie's picture rate. Presents follow that hold instead of the interval the game sets. `DM_FPS_TARGET` overrides it; the log line `frame step: game time … of real time` checks the game's speed. On a `main` without a frame step the host keeps the game's own present interval whatever `fps_target` or `DM_FPS_TARGET` says, except with `present_interval display`, where the cap is the present interval alone. Ocarina of Time sets 60 |
| `fps_max` | `60` (the default) or `120`: the highest rate `fps_target` and the player's **Frame rate** take. 120 needs an engine frame limit the host writes, of which this tree has none (`hle_nvn.c` `fps_high`), so a `main` with a frame step runs at 60 ([120 fps follows the frame step](../../docs/reference/frame-rate.md#120-fps-follows-the-frame-step)) |
| `fps_hold` | `on` (the default): with `fps_target`, three late frames in a row raise the hold above the cap's vsyncs (30 or 20 fps) when the last 30 frames also fall short of the cap on average, and steady frames that fit try the lower hold again. `off`: frames are never held longer than the cap's vsyncs; each is shown as soon as it is ready. `DM_FPS_HOLD=on` / `off` overrides it |
| `core_preempt` | `on` / `off` (the default): additionally check higher-priority runnable threads pinned to the caller's core after every thread SVC (`hle_thread.c`). `DM_PREEMPT=0` / `1` overrides it. Wake-triggered same-core handoffs apply with either setting ([Same-core wake handoffs](../../docs/reference/threads.md#same-core-wake-handoffs)) |
| `depth_mode` | `gl` (the default, NVN's near = −w) or `zero` (near = 0): the depth mode the game sets with `nvnDeviceSetDepthMode`, for the pipelines made before the game runs: the pipeline archive made offline (`dm/gfx/tools/pso_offline.py`) and the packing script's prebuild (`DM_PSO_PREBUILD_DEPTH`). The host itself follows the mode the game sets. It is no shader input |
| `op_mode` | The operation mode the game sees at start: `console` (the default, docked) or `handheld` (`hle_oe.c`). `DM_OPMODE=0` / `1` overrides it, as the launcher's **Console mode** does |
| `perf_mode` | `follow` (the default): the performance mode follows the operation mode (Boost docked, Normal handheld); `boost`: Boost whatever the operation mode (`hle_oe.c`) |
| `tex_flush_upload` | `on` / `off` (the default): a texture the game fills from the CPU in place (no packaged layout, no `WriteTexels`) and publishes with `nvnMemoryPoolFlushMappedRange` is uploaded from guest memory like a packaged one, and re-uploaded when its pages change (`ft_add` in `hle_nvn.c`). Off by default because a flushed range could cover an image a shader writes, whose GPU content the upload would replace. Without the key, a texture still gets its storage once when the game flushed it before the texture's first use (`nvn_flushed` in `hle_nvn.c`); the key is for textures the CPU writes again after that. Ocarina of Time sets it on |
| `tex_dirty_upload` | `on` / `off` (the default), needs `tex_flush_upload`: a registered texture whose pages the CPU writes after `nvnTextureInitialize` without any NVN flush is uploaded as well (its pages are write-protected at registration, checked on first use; `nvn_ft_written` in `hle_nvn.c`). Ocarina of Time writes its terrain tiles' height, blend and hole maps this way, and without the two keys has holes in the ground |
| `tex_dyn_slots` | `on` / `off` (the default): a shader whose buffer-texture handle the translator could not trace to one slot gets Ryujinx's fallback arrays (`<stage>_<tb|s>_cb0_40000000`; [Texture handles from game memory index the pools](../../docs/reference/shaders.md#texture-handles-from-game-memory-index-the-pools)). With the key the replay puts slot indices in that shader's c2 texture and sampler tables and binds slot k at element k, so the shader's own arithmetic picks the binding (`NVN_RB_TEXD` / `NVN_RB_SAMPD` in `nvn_mtl.m`). Right only where the handle comes from c2's tables. Not part of the shader chain version |
| `draw_barriers` | `full` (the default) / `game`: how draw passes are ordered. `full`: each waits for all earlier GPU work. `game`: by the game's own barriers (NVN asks for one before results of rendering are read), so a pass's vertex work overlaps the previous pass's fragments. Ocarina of Time sets `game`: GPU time 25 → 18 ms, about 180 full barriers a frame halved. Only a barrier that orders primitives or indirect data waits for all earlier work; a fragment-only one keeps the overlap. `DM_NVN_BARRIER` overrides it |
| `replay_ahead` | `off` (the default) / `on`: a queue parked on an event the game's CPU signals is translated before the signal, its commits held until then; needs `enc_thread` ([The GPU waits at a frame's start for commands the game queued long before](../../docs/reference/frame-rate.md#the-gpu-waits-at-a-frames-start-for-commands-the-game-queued-long-before); `DM_NVN_REPLAY_AHEAD` overrides). Ocarina of Time sets it on |
| `upscaler_sharpness` | `0.0` to `1.0` (the default): with `DM_UPSCALER=metalfx`, the share of MetalFX's own picture in the game's image, the rest the scaler's input scaled bilinearly; the launcher's **3D upscaler sharpness** starts from it (`DM_UPSCALER_SHARPNESS`). Ocarina of Time sets `0.7` |
| `gpu_ts_hz` | The tick rate of the raw counter timestamps a timestamp report writes, in Hz (default `0`, the game's NVN: 614.4 MHz on NVN, nanoseconds on NVN2, [NVN2 timestamps are nanoseconds](../../docs/reference/frame-rate.md#nvn2-timestamps-are-nanoseconds)). `31250000` for a Switch 2 game that reads raw reports at the Switch 2's system counter rate (Ocarina of Time's wind and particle time step); `DM_NVN_TS_HZ` overrides it |
| `vconv_range` | `on` / `off` (the default): vertex attributes the replay converts on the CPU (`vconv_bind` in `nvn_mtl.m`) are converted only over the vertices each draw reads instead of the whole bound range. Indirect draws, per-instance streams and indices with a GPU write queued on them keep the whole range. `DM_NVN_VCONV_CHECK=1` scans the indices again at every reuse and reports differences; `DM_NVN_VCONV_RANGE=0` / `1` overrides it |
| `shader_key_skip` | `<offset>+<length>` (none by default): control-section bytes every shader key hashes as zeros, in `shader_split.py` (`key_ctl`) and the host (`hle_nvn.c` `keys_hash`), for an engine that shares one control section among shaders that differ only there. It must stay clear of `+0x700..+0x75f`, which the tools read; it is a shader chain input, as every `shader_*` key |
| `shader_groups`, `shader_note` | `shader_split.py` source groups and the map header note. Both are shader inputs, the note too: changing either one, even by a word, builds every shader of the game again |

### What the game files decide at every build

These are not profile keys: the tools read them from the game's files each time.

- **Shader containers.** `shader_split.py` scans every file of the RomFS (zstd files decompressed with the dictionaries of `Pack/ZsDic.pack.zs`, SARC archives member by member) and `main` for the containers the game ships: BNSH (in `bfsha`, particle effect and UI layout files, and embedded in `main`), agl's BAHS packs, the NDSR upscaler packs and nn::ndve's movie enhancement file. Its file header has the layouts.
- **The upscaler's shaders.** `game.py` takes the keys of the game's own upscaler from the shader map's source column: the compute shaders of an NDSR pack (`DM_GAME_UPSCALER_KEYS`), and those of agl's variable-ratio chain, `agl_ndsr_vr.pck` and `agl_ndsr_vr_light.pck` (`DM_GAME_UPSCALER_CHAIN_KEYS`). A profile with any offers the launcher's **3D upscaler**.
- **Stubs the rewriter placed.** `patch_nso.py` writes what a build's stubs offer into `main.fixups.tsv` (`DYNAMIC_RESOLUTION`), and `settings.py` offers the launcher rows of those the table has.
- **Languages.** `settings.py` lists the languages of the NUP's control data; a NUP without that list gets every language, with a note.
- **Microphone.** `settings.py` offers the microphone rows when a rewritten module imports the SDK's polling input stream (`nso_syms.audio_input_capable`).
- **NVN driver tables.** The driver's constant segments have one layout (`dmsh_build.py`, filled by `nvn_mtl.m`): c2 holds the handles bound with `nvnCommandBufferBindTexture` at `0x20 + 8 × slot`, images at `0x120 + 8 × slot`, separate textures at `0x168 + 8 × slot` and separate samplers at `0x568 + 8 × slot`; c0 the storage buffer tables (vertex 0x110, compute 0x310, pixel 0x510). Separate texture binds are texture slots 128 + n of the host's table (`NVN_SEPTEX_SLOT0`), so a game may bind both kinds in one frame. The translator (`dmsh_xlate/Program.cs`) numbers slots the same way when it looks up per-slot texture / image types in `shader_facts.tsv`.

## A new version of the game

The profile registers the builds it was brought up on (`build` rows). The packing script builds any other version of the game too, from a **derived profile**:

1. **Build it.** Run `scripts/build_app.py` on the NUP that holds the version. It builds the newest version in the NUP (`-p` / `PACKAGE` picks another). When that version has no `build` row, when a module's build ID is not the one its row names, or when the NUP lacks a version in `shader_versions`, the script says so and writes a derived profile to `<build folder>/profile/<title ID>/` (`--profile-out` / `PROFILE_OUT` names another place; `derive_profile`): the repository profile's keys, that version's own `build` row, `package` and `shader_versions`, and shader tables made from that version's files alone. The hand-written tables (the prewarm list among them) are copied. When only the NUP's DLC adds shaders to a registered version, the derived profile is a shader-only one: it keeps the registered `build` rows and patches, with shader tables of its own. The tools find it through `DM_GAMES_DIR` with `DM_GAMES_FIRST=1`, which the script sets.
2. **Read what it reports.** Build-keyed patches (`CUTS`, `OBS`, `FRAME_STEP`, `STUBS`) and host code gated by a build ID do not run on a build they were not found in. Function-matched patches (`MATCH_CUTS`, `MATCH_FRAME_STEP`) apply where their function's fingerprint still matches exactly once: the rewriter lists each patch's result in `<module>.match.tsv`, and the script ends with the patches applied and a red line for each that was not, and for a version the profile does not register. Ocarina of Time's patches are all function-matched. A derived profile whose `main` has no frame step, while the profile has build-keyed ones for other builds only, gets `fps_target 0`.
3. **Register the version** once it is checked: add its `build` row to the profile's `game.tsv` (the derived profile's `game.tsv` has it, with each module's build ID). The shader tables stay those of the versions `shader_versions` names, and the split checks them against those versions' files. Carry any fixed address over with `python3 dm/tools/nso_fnmap.py <old .orig.bin> <new .orig.bin> 0xoffset…` (the images come from `dm/tools/nso.py`) and check it by disassembly; never let a fixed address run on a build it was not found in. For a function-matched patch that no longer matches, review the function in the new build the same way and add its implementation as [Function-matched cuts](../../docs/reference/rewriter.md#function-matched-cuts-for-unregistered-builds) describes. Record what was checked in the game's note.
